# Poteto help

Cindy adaptation: only /poteto-mode is registered. Other slash names in this upstream reference denote bundled files in the entry index, not installed commands. Cursor setup, Custom Modes, /loop, and Cursor plugin installation are not supplied here. Report unavailable capabilities instead of instructing the user to install Cursor components. Linked upstream documentation is not bundled; if offline or inaccessible, report it unavailable and do not claim to have read it.

Answer the user's question about pstack, hand them a prompt they can send, and link the file the answer came from. For a help question, don't start the work. The user asked how, and a pstack run spends real tokens, so let them send the prompt.

A message that asks for work, such as "use pstack to fix this bug", is not a help question. Read [`poteto-mode`](../../SKILL.md), do the work under it, and use the available Cindy entry.

This file maps questions to the skills and guide pages that hold the answers. Those files own the details. Read the file you route to before you quote it, and trust it when it disagrees with this map. The links here point into the installed plugin, which the user may not be able to open, so give the user the file's public copy: `https://github.com/cursor/plugins/blob/2776ddd2355d6d6c8747d3964600f28daf62f049/pstack/` followed by its path.

## Find out what they need

Infer the need from the message and the conversation. A named situation, such as "which skill reviews a PR?", goes straight to its section. If the need is still unclear, ask one multiple-choice question with these options, then answer only the section they pick:

- Get set up
- Start a task with `/poteto-mode`
- Pick a skill for a situation
- Fix a run that went wrong
- Make pstack my own

## Get set up

Install and enable this Cindy plugin, then invoke `/poteto-mode` with a goal and a verifiable check. Only that entry is registered. Other pstack skills are references linked in its index. Cursor model setup and Custom Modes are not provided; choose among models available in the current Cindy engine. Explain missing tools and permissions rather than promising Cursor features.

## Start a task with `/poteto-mode`

`/poteto-mode` matches the task to a playbook, copies the playbook's steps into the todo list, and runs the other skills as the steps need them. A step it skips stays in the list as `skip: <reason>`. A good prompt states the goal and how to tell it's done. It doesn't list skills, because a hand-written sequence tends to drop or reorder steps the playbook would keep. Read [`references/prompting.md`](references/prompting.md) before you help word one. [Guide page 2](https://github.com/cursor/plugins/blob/2776ddd2355d6d6c8747d3964600f28daf62f049/pstack/docs/guide/02-poteto-mode.md) has examples.

Invoke `/poteto-mode` for each task as supported by the current Cindy engine. For delegates, use available general-purpose agents with the complete bundled agent prompt and the entry realpath.

Close calls:

- `how (bundled reference; see entry index)` explains what the code does. `why (bundled reference; see entry index)` explains the reasons. `teach (bundled reference; see entry index)` runs one or both and explains the result plainly.
- `arena (bundled reference; see entry index)` gives every worker the same brief and merges the best parts. `swarm (bundled reference; see entry index)` splits work into slices or a race and returns one report.
- `architect (bundled reference; see entry index)` implements right after it settles the design. Add "with checkpoint" to review the design before it writes code.
- `interrogate (bundled reference; see entry index)` reviews the diff. `blast-radius (bundled reference; see entry index)` looks for breakage outside the diff and proves the one fact that makes the change safe.
- `recall (bundled reference; see entry index)` rebuilds context across recent chats. `ketchup (bundled reference; see entry index)` covers only this chat since the user's last message. Resuming one specific chat or branch is the Session pickup playbook.
- `figure-it-out (bundled reference; see entry index)` designs one rigorous run. The Orchestrate playbook runs a program that spans days and many PRs. The Autonomous run playbook drives one task to a finish condition.

Bundled references include unslop and no-comments. Cindy terminal tools and cindy_browser depend on the current session. Cursor /loop is not bundled.

## Playbooks and principles

Playbooks are step lists inside `/poteto-mode`, not skills, so they have no slash command. Inside `/poteto-mode`, describing the task picks one, and these phrases name one directly:

- "babysit this pr" or "check on pr 123" runs Babysit. It drives the PR to merge-ready and stops there. It doesn't merge unless the user asks to merge, land, or ship.
- "land the stack" runs Shipping.
- "take over this branch" runs Session pickup.
- "pause safely" runs Pause safely.
- "full autopilot on this queue" runs Autopilot-full. "autopilot, don't merge" runs Autopilot-stack.
- "run the eval playbook" runs Eval.

Invoke `/poteto-mode` to use these playbooks in Cindy. The Playbooks section of [`poteto-mode`](../../SKILL.md) lists every playbook and when it applies. [Guide page 6](https://github.com/cursor/plugins/blob/2776ddd2355d6d6c8747d3964600f28daf62f049/pstack/docs/guide/06-verify-and-ship.md) covers opening, babysitting, and landing a PR.

pstack has no planning skill. Use planning capabilities available in the current engine. For work that spans phases or stacked PRs, asking `/poteto-mode` for a plan runs the [Multi-phase plan playbook](../../playbooks/multi-phase-plan.md), which writes the plan and doesn't implement it. For a design question, the Prototype playbook or `architect (bundled reference; see entry index)` settles it in code first.

Principles are one-rule skills that `/poteto-mode` reads and cites in its replies. The user rarely invokes one. They steer with the names instead, as in "apply prove it works. show me the real output." Read the matching principle reference from the entry index. [Guide page 8](https://github.com/cursor/plugins/blob/2776ddd2355d6d6c8747d3964600f28daf62f049/pstack/docs/guide/08-principles.md) lists them.

## Fix a run that went wrong

| Symptom | Fix |
|---|---|
| The mode stopped applying after a few turns | Start each task with `/poteto-mode` as supported by the current engine. |
| A question got treated as the next step of the last task | Say "new task", or say the turn doesn't need the mode. |
| A new model choice had no effect | Cindy does not install a Cursor model rule. Check the model actually available in the current session. |
| Runs cost more than expected | Check model and execution costs for the current engine. |
| A skill didn't load on its own | Only `/poteto-mode` is registered; the other bundled workflows are references the entry reads as needed. |
| Parallel agents overwrote each other | Give each agent its own worktree, or run them as cloud agents, which each get their own machine. |
| An overnight run moved but finished nothing | Cursor /loop is unavailable; use an authorized supported wake mechanism or stop and report it. See [guide page 7](https://github.com/cursor/plugins/blob/2776ddd2355d6d6c8747d3964600f28daf62f049/pstack/docs/guide/07-overnight.md). |
| The reply claims success from a green build | Ask for the real command, flow, stored value, or profile. That's the prove-it-works principle. |

For a run that drifts, [`references/prompting.md`](references/prompting.md) has one-line steers. [Guide page 10](https://github.com/cursor/plugins/blob/2776ddd2355d6d6c8747d3964600f28daf62f049/pstack/docs/guide/10-recipes-and-pitfalls.md) has more pitfalls and the recipes worth copying.

## Make pstack my own

- [`automate-me (bundled reference; see entry index)`](../automate-me/SKILL.txt) drafts a personal mode skill from the user's own history, to use alongside `/poteto-mode`.
- [`reflect (bundled reference; see entry index)`](../reflect/SKILL.txt) after a session turns its lessons into skill edits the user approves.
- `/poteto-mode write a skill for <workflow>` runs the authoring playbook. The eval playbook tests a skill change blind.
- Fix a misbehaving skill in its own PR, not inside the feature work where it went wrong.

[Guide page 9](https://github.com/cursor/plugins/blob/2776ddd2355d6d6c8747d3964600f28daf62f049/pstack/docs/guide/09-make-it-yours.md) covers each of these.
